# Adaptive Memory — Phases 3 to 7

## Status

Implemented on `chatgpt/adaptive-memory-full` on top of merged Phase 1 and Phase 2.

## Phase 3 — Accepted example memory

`AcceptedExampleMemory` keeps a bounded local set of fully accepted completion patterns. Long literals and large numeric values are normalized before persistence. Retrieval is lexical and scores structure/object match, token overlap, reuse, and recency. `CompletionPromptBuilder` injects at most two retrieved patterns.

## Phase 4 — Observed ABAP object index

`ObservedAbapObjectIndex` stores lightweight ABAP skeletons generated by the existing `RelatedFileCollector.extractAbapSkeleton`. It reindexes only after source hash changes, trims by recency, and contributes at most three related remembered objects to a prompt.

## Phase 5 — Adaptive model router

`CompletionContextClassifier` assigns completions to buckets such as RAP, Open SQL, method body, class definition, and generic ABAP statement. `AdaptiveModelRouter` combines the existing static resolver score with persisted acceptance, post-accept edits, dismissals, and superseded suggestions. Context-specific data is used only after a minimum sample threshold; Bayesian smoothing prevents one lucky completion from moving routing materially.

Manual model selection is never overridden by adaptive routing.

## Phase 6 — Completion reranking

`CompletionReranker` ranks multiple candidates locally using structural validation, learned style, accepted-example similarity, historical model/context quality, latency, and length penalties. The current gateway path still returns one candidate, so reranking becomes active when a caller/gateway supplies multiple candidates; no JSON response contract is introduced.

## Phase 7 — Controls and diagnostics

A child preference page is registered at:

`Preferences > AI Code Assistant > Adaptive Learning`

Controls include:

- enable/pause local learning;
- bounded example/object memory size;
- reset all learning;
- reset accepted examples;
- reset object memory;
- reset feedback counters;
- aggregate diagnostics refresh.

## Persistence/privacy

Adaptive state is local to the Eclipse plugin state directory. Style and feedback remain aggregate metrics. Accepted examples are normalized and bounded. Object memory contains skeletons rather than full documents. API keys, authorization headers, prompts, and remote telemetry are not part of adaptive storage.

## Test coverage

`AdaptiveLearningTests` covers style learning, feedback round-trip/rates, accepted-example retrieval/persistence, object-index retrieval/persistence, context classification, adaptive model routing, and local reranking. `build.ps1` executes both `CoreTests` and `AdaptiveLearningTests`.
